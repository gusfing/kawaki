(01) — The Spam Vectors

How SEO Spam Infects WordPress Sites

Attackers hijack your domain authority to rank thousands of spam landing pages on Google without altering your visible homepage.

The Japanese Keyword Hack

Attackers inject automated PHP scripts that dynamically generate tens of thousands of indexed pages in Japanese. These pages target counterfeit goods, luxury accessories, and fraudulent e-commerce storefronts, heavily damaging brand reputation.

Pharma & Gambling Injections

Malicious links and keyword clusters targeting illicit pharmaceutical products (Viagra, Cialis) or casino gaming are injected into your posts, footer templates, or dynamically served via WordPress shortcode filters.

Virtual Dynamic Spam URLs

Instead of creating physical files for every spam page, intruders alter .htaccess or hook into the WordPress template_redirect action. Requests matching specific regex patterns dynamically render spam pages on the fly while leaving the filesystem seemingly clean.

Search Engine Cloaking

The injection checks the HTTP_USER_AGENT header. If Googlebot or Bingbot is detected, the server returns spam-laden HTML. If a standard user visits, it renders normal company pages, allowing the infection to go unnoticed for months.

Rogue XML Sitemaps

Attackers upload fake sitemap files (e.g., sitemap_index_spam.xml) directly to your web root and submit them through compromised Google Search Console properties or ping endpoints, accelerating indexation.
(02) — Technical Diagnosis

Uncovering Hidden Cloaking & Injections

Because SEO spam actively hides from website administrators, diagnosing it requires simulating search engine crawler environments and directly interrogating database tables.

1. User-Agent Emulation via CLI

We execute automated HTTP requests using custom User-Agent strings (Googlebot/2.1) and verified Google IP simulation headers to trigger cloaked responses and capture the malicious payload.

2. Direct Database Content Sanitization

Injected links often hide inside the wp_posts table in base64 strings or hidden CSS wrappers (e.g., display:none). We run structured SQL queries to isolate and strip malicious injected content without damaging valid copy.

3. Template & Hook Interception

We inspect active theme templates, functions.php, and core hooks (wp_head, the_content, wp_footer) for conditional filters injecting spam links at render time.

4. Search Console & Index Audit

We cross-reference Google Search Console indexing reports to identify newly submitted rogue sitemaps, unauthorized property owners, and sudden spikes in indexed URLs.

(07) — Frequently Asked Questions

Common Questions on SEO Spam & Japanese Hacks

What is the Japanese keyword hack on WordPress?

The Japanese keyword hack is an SEO spam attack where an intruder compromises WordPress and injects thousands of autogenerated pages filled with Japanese text promoting counterfeit luxury goods, electronics, or illicit merchandise. These pages often register fake sitemaps and use conditional cloaking so website administrators see normal pages while search engine crawlers are served Japanese spam, causing search results to show Japanese titles and snippets.

Can you guarantee that our previous Google rankings will be restored?

No. Search engines independently control crawling schedules, indexation, and algorithmic ranking decisions. We clean the injected spam, remove malicious code, resolve cloaking, and configure technical response headers (such as HTTP 410 Gone) to help search engines recognize that spam content is gone. However, no agency can guarantee specific ranking outcomes or timelines.

Why do spam pages appear in Google when I cannot see them on my site?

This symptom is caused by conditional cloaking. The malicious script or .htaccess rewrite rule inspects the HTTP User-Agent and visitor IP address. When an administrator or normal visitor requests the URL, the server returns the normal page or a standard 404. When Googlebot or Bingbot crawls the page, the script dynamically serves the spam payload. We diagnose cloaking by emulating search engine crawlers directly via curl.

How do you handle thousands of indexed spam URLs?

Rather than letting spam URLs return standard 404 Not Found headers, we configure the server to return HTTP 410 Gone headers for the identified spam URL patterns. A 410 status explicitly informs search engine crawlers that the resource was intentionally removed and will never return, prompting search engines to de-index the URLs more rapidly than passive 404 responses.

Where does SEO spam usually hide inside WordPress?

SEO spam typically hides in multiple locations: the database (wp_posts, wp_postmeta, and wp_options tables), template files (header.php, footer.php, functions.php), rogue sitemap XML files dropped in the root directory, or standalone PHP page generators placed in wp-content/uploads/ or hidden directories that hook into WordPress rewrite rules.

What should we provide to begin the SEO spam cleanup?

To perform a thorough investigation and cleanup, we require SFTP or SSH access to your hosting server, administrative access to your WordPress dashboard, access to your database management tool (such as phpMyAdmin or CLI), and delegated user access to your Google Search Console property to inspect indexing data and submit remediation requests.
