// 02. PROJECT BRIEF

Strategic Mandate & Operational Objectives

Institutional Context

Pixza is a flagship generative AI web application engineered from the ground up by Kawaki Studios. Designed for digital artists, content creators, and growth marketing teams, Pixza eliminates the fragmented tooling and prohibitive subscription tiers of traditional AI image platforms. It combines an editorial dark-mode interface with multi-provider model routing, personal ChatGPT OAuth proxying, intelligent token rotation failover, and 'Flow Mode'—a visual node canvas for batch generation.

As a proprietary in-house product, Pixza serves as concrete empirical proof of Kawaki Studios' ability to conceptualize, architect, and deploy production-grade software capable of handling high-concurrency generative workloads across globally distributed edge nodes.

STRATEGIC IMPERATIVE

Most generative AI tools force creators into rigid single-model silos with monthly $30+ subscription fees. When third-party APIs experience downtime or hit rate limits (HTTP 429), creation freezes. Creators needed a unified creative canvas capable of orchestrating open-weight and proprietary models with automatic failover and zero client-side key exposure.

Verified Project Objectives

OBJ 01

Eliminate API Rate-Limit Generation Failures (HTTP 429)

Build an automated multi-key token rotation engine with sub-15ms failover to reserve keys, ensuring creative prompt generation never freezes.

OBJ 02

Unify Open-Weight & Proprietary Model Inference

Abstract divergent API contracts from HuggingFace Spaces (FLUX Schnell, Qwen Fast), Cloudflare Workers AI, and OpenAI into a single normalized edge routing layer.

OBJ 03

Engineer Flow Mode Visual Node Canvas

Develop an interactive node graph enabling digital creators to visually connect prompt nodes, compare concurrent model outputs side-by-side, and run batch generation.

OBJ 04

Enforce Zero-Retention Cryptographic Security

Encrypt user API credentials client-side via AES-256-GCM before local storage, ensuring zero server-side retention of private keys or user generation histories.

// 03. THE CHALLENGE & THE APPROACH

Operational Friction vs. Architectural Strategy

THE VERIFIED CHALLENGE

Real Constraints & Friction

Eliminating API rate-limit bottlenecks and model lock-in by orchestrating multi-provider AI inference on serverless edge runtimes.

API Rate-Limit Failures (HTTP 429)

AI API keys frequently hit sudden rate limits during peak creative sessions, causing prompt generations to fail and frustrating creators.

Multi-Provider Model Fragmentation

Creators must switch between Midjourney, DALL-E, and open-weight models (FLUX, Qwen) across different websites with inconsistent prompt syntax and aspect ratio controls.

High Subscription Costs & Barrier to Entry

Forcing users to buy separate recurring monthly credits for each AI provider creates high friction. Pixza needed to let users leverage free edge allocations and personal ChatGPT subscriptions.

Key Storage Security & Privacy

Storing user-provided third-party API keys on central agency servers creates security vulnerabilities and legal liability in the event of database breaches.

Batch Generation & Prompt Chaining UX

Traditional linear chat-box interfaces make it difficult to compare outputs between models or iterate on variations across multiple aspect ratios.

THE KAWAKI APPROACH

Architectural Response

We designed Pixza on an edge-native, zero-retention philosophy. Generative AI should not be locked behind bloated containers or single-vendor monopolies. By pairing modern React 19 with Cloudflare's global edge network, inference happens in milliseconds with automated failover and local cryptographic security.

Edge-Native Stack: React 19 & Hono 4

We decoupled frontend presentation from backend compute by deploying React 19 on Cloudflare Pages and Hono 4 on Cloudflare Workers, achieving sub-100ms cold starts worldwide.

Enterprise Token Rotation Engine

We built a multi-key rotation arbiter that dynamically cycles through API tokens, automatically failing over to backup keys upon encountering HTTP 429 rate limits.

Personal ChatGPT OAuth Proxy

We engineered a direct OAuth integration allowing users to authenticate their personal ChatGPT accounts (Free, Plus, Team) to generate via DALL-E-3 and refine prompts via GPT-4o.

Flow Mode Node Canvas

We designed an interactive visual canvas allowing users to connect prompt nodes, compare concurrent outputs across different models, and execute batch runs.

Client-Side AES-256-GCM Encryption

API credentials are encrypted locally in the user's browser before storage, ensuring zero plain-text key exposure on server logs.

// 06. ARCHITECTURAL & CRAFT DEEP DIVE

Production Engineering & System Hardening

A detailed examination of the verified fullstack infrastructure, state hydration boundaries, and API gateways powering Pixza.

01 / Frontend & Client Runtime

Engineered using React 19, incorporating concurrent rendering features, action hooks, and optimized state machines to maintain 60fps canvas performance during multi-image generation.

02 / API & Real-Time Gateway

Universal inference adapter abstracting divergent REST, WebSocket, and SSE streaming payloads from HuggingFace, OpenAI, and Cloudflare AI into a unified JSON response contract.

03 / State Management & Persistence

Zero-retention architecture. Session state and generation history reside exclusively in client-side IndexedDB and localStorage.

04 / Security & Performance Discipline

Sub-100ms cold starts on Cloudflare global edge network. Zero heavy image blob retention in memory prevents browser tab crashes during long creative sessions.
