## Content Production Workflow

### Per Piece Process (2-Week Sprint)

| Stage | Duration | Owner | Deliverable |
|-------|----------|-------|-------------|
| **Research & Outline** | 2 days | Strategist | Outline + keyword map + competitor gaps |
| **Draft** | 5 days | Writer | First draft (target word count) |
| **Technical Review** | 2 days | Senior Dev | Code accuracy, implementation details |
| **Design/Visuals** | 2 days | Designer | Diagrams, screenshots, charts |
| **Edit & Optimize** | 2 days | Editor | SEO optimization, schema, internal links |
| **Publish & Promote** | 1 day | Marketing | CMS publish, social, newsletter, outreach |

### Quality Gates (Pre-Publish Checklist)

- [ ] Target keyword in H1, first 100 words, 2+ H2s
- [ ] 3+ internal links to service/industry/case study pages
- [ ] 2+ external links to authoritative sources
- [ ] Schema markup validated (Rich Results Test)
- [ ] Images: AVIF/WebP, explicit dimensions, alt text
- [ ] Author bio with Person schema
- [ ] Reading time < 12 min (or split into series)
- [ ] Mobile preview verified
- [ ] Core Web Vitals impact assessed (no heavy JS)

## Content Governance

### Style Guide References
- **Voice:** Editorial, precise, confident — not salesy
- **Tone:** Senior engineer speaking to technical buyer
- **Formatting:** H2 every 300 words, bullet lists, code blocks, tables
- **Citations:** Link to primary sources (specs, RFCs, official docs)
- **Schema:** Every page has appropriate schema (validated)

### Update Schedule (Quarterly)
- Service pages: Update metrics, add new tech, refresh case study links
- Industry pages: Add new regulations, trends, case studies
- Guides: Verify code examples still work, update version numbers
- Research: Archive, create "202X vs 202Y" comparison

### Archive Policy
- Content >2 years old without updates → add "Last updated" banner
- Content >3 years old with <10 sessions/mo → redirect to newer equivalent
- Never delete — redirect or update
